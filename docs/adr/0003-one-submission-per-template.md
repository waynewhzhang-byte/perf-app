# 0003 — 一人一模板一份申报，upsert 覆盖

**Status:** accepted (2026-06-13)

`Submission` 复合 unique `[userId, templateId]`：同一员工对同一模板只能有一份申报，
DRAFT/SUBMITTED/REJECTED 共用同一行，新提交覆盖旧行。**不**为草稿/已提交/已驳回分离存储多版本。

原因：年度绩效申报每年提交一次，无并发版本冲突场景；员工对一份模板有"历史草稿"无业务价值，
反而增加"哪个版本是真正提交的"歧义。状态机字段 `SubmissionStatus` 表达单条记录的生命周期，
而不是创建多条记录。

后果：申报的"版本历史"只能从 `ReviewLog` 推断，不能从 `Submission` 表回溯多版。
若未来需要保留草稿版本（如多人协作起草），需要重新设计此约束。
