## 已拍板决策（执行契约）

> 实现与评审必须以本节为准。UI 文案可写「确认报名」，领域词用「确认无异议」。

| ID | 主题 | 决定 |
|----|------|------|
| G1 | 审核对象 | 系统填充/事实维度**只审申诉**；无申诉经确认无异议后**跳过 L1/L2 待办并直通归档**（ADR-0008）。有申诉时非申诉项也不进审核台。 |
| G2 | 申诉分 / 审核确认 | 「申诉分值」= **主张分**（`disputeClaimedScore`），仅供参考。审核「确认」= **申诉理由成立**，**不改**该项最终分；改数只走**事实修正**。不恢复 override API。 |
| G3 | 归档时点 | 无异议确认，或全部申诉审结（确认/驳回）后，按**当时系统分**写入 `PerformanceRecord` 快照。不因「待事实修正」阻断归档。 |
| G4 | 申诉路由 | **L1**：按申报人所属工区（及总部 L1 部门 scope）。**L2**：按申诉项 `dimensionCode` 的「二审归属配置」投递总部部门。多申诉可拆到不同 L2 部门。「所有申诉记录」= 该申报人在**本审核员 scope 内**的申诉行，非系统全局。 |
| G5 | 驳回范围 | 任一申诉「驳回」→ 整单 `REJECTED` 退回员工，沿用**驳回重提**（仅驳回项可改）。P0 不做行级并行驳回。 |
| G6 | 申诉保存 | 弹窗「保存」= 写入申报**草稿**（`DISPUTED` + 主张分/理由/附件），申报仍可编辑、**未进审核队列**；仅「提交审核」送 L1。提交前可编辑/删除已保存申诉。 |
| G7 | 蓝框说明 | **保留**蓝框并改文案；废弃原表「2 蓝框部分删掉」。文案去掉「逐项确认」，改为只读核对 + 底部申诉 + 确认无异议。 |
| G8 | 双 CTA 互斥 | 无已保存申诉 → 仅「确认报名」（确认无异议 / AFFIRM）可用，「提交审核」灰掉。有已保存申诉 → 仅「提交审核」（APPEAL）可用，「确认报名」不可用；删光申诉后恢复 AFFIRM。两者均需防误触确认弹窗。 |
| G9 | 计算过程 | **复用**现有 `fact-derivation` / 绩效分表步骤展示（可截断+展开）；**禁止**新建计分/推导引擎。展示形态对齐原表示例（两票/缺陷拼接说明）。 |
| G10 | 交付切分 | **P0 必须同发**：删逐项确认/申诉 UI + 底部申诉 + 双 CTA + 只审申诉/直通归档（原 R3+R4+R5+R7）。**P1**：审核表格批量（R8）。**P2**：强制阅读弹窗、标题/表头润色、技术电话可编辑（R1/R1b/R1c/R2 润色/R6）。 |

## 1. 员工界面 — 登录后强制阅读弹窗

**改动**

员工界面：登录成功增加弹窗，弹窗内容为申报工作相关要求，弹窗不能关闭，30 秒强制阅读，点击确认继续后才可进入申报界面，显示评分标准。

**实现效果（弹窗文案）**

为确保公司 2025 年能级评价量化积分填报工作的严肃性、准确性和保密性，请注意以下事项：

一、认真如实填报

请本着对公司和本人负责的态度，仔细阅读填报说明，结合本人实际情况逐项核对，确保信息真实、完整、准确。对于评价内容有任何疑问，请及时与相关部门沟通确认。

二、严格遵守保密规定

本平台所填报的量化积分信息属于公司内部敏感信息，请严格遵守保密纪律，严禁向无关人员透露，严禁截图转发、外传或以其他任何形式泄露给第三方。

三、相关后果

如发现漏报、瞒报、虚报或泄露相关信息，公司将依据有关规定追究相应责任。

感谢您的理解与配合！让我们共同维护能级评价工作的规范性和安全性。

（30 秒倒计时）按钮「我已认真阅读，确认继续填报」

**执行说明（P2）**

- 本项属 P2，不阻塞 P0。
- 弹窗是否管理端可编辑、出现频率（每次登录 / 每模板一次）、是否落库确认记录：**未在本次 grill 拍板**，实现 P2 前需另定；在此之前可用硬编码文案。

## 2. 员工申报表界面 — 维度结构与计算过程

**改动**

员工申报表界面。

**实现效果**

按能级评价量化积分表 4 个一级维度划分「基本素质」「工作业绩」「工作现场」「特殊事项」（与 `SCORING_STANDARDS` 一致；旧称「一票否决」不用）。

每个一级维度及得分下显示二级维度及得分；叶级（三级）显示评价标准、得分、计算过程。

结构：

- 一级维度：得分
- 二级维度：得分
- 叶级：评价标准、得分、计算过程

**执行说明（已拍板，见 G9）**

计算过程复用 `fact-derivation` 步骤；展示可截断 + 展开。参考形态：

- 两票：`操作票58项+工作负责人总工作票5份+…`
- 缺陷：`重大缺陷第一发现人2次+较大缺陷共同发现人1次+…`

## 5. 员工申报表界面 — 底部导航与提交流程

**改动**

最下方导航：「申诉」「确认报名」「提交审核」

- 「确认报名」= 确认无异议（AFFIRM，G1/G8）
- 「提交审核」= 存在**已保存**申诉后的送审（APPEAL）；不是「点过申诉按钮」即可

**实现效果（按钮逻辑，已拍板 G8）**

1. 无已保存申诉：「提交审核」灰色；「确认报名」→ 防误触弹窗 → AFFIRM → 直通归档。
2. 有已保存申诉：须先保存申诉；「确认报名」不可用；「提交审核」→ 防误触弹窗 → APPEAL → 仅申诉进审核。
3. 路由见 G4：L1 工区 + L2 维度二审归属部门。

## 7. 审核员端 — 仅处理申诉

**改动**

一级/二级审核工作台**只处理用户端申诉**（G1 / ADR-0008）。

**实现效果（已拍板）**

- **无申诉**（确认无异议）：不进待审，直接归档（G1/G3）。
- **有申诉**：按 G4 出现在对应 L1/L2 工作台；可见范围为该人在本 scope 内全部申诉行。
- 审核「确认」/「驳回」语义见 G2/G5；确认不改分；驳回整单退回。

---

## 8. 审核员端 — 待审核/已审核表格化 UI

**改动**

待审核 / 已审核左侧切换保留；主区改为申诉行表格（P1，G10）。

列：勾选框，序号，工号，申诉人，申诉项，系统分值，申诉内容，附件（可预览），申诉分值（主张分），审核（确认/驳回）。

支持申诉项筛选、关键字筛选；批量确认 / 批量驳回（驳回须原因；批量驳回按 G5 导致相关申报整单退回）。

已审核：审核列状态写死为「确认」或「驳回」。

**执行说明**

- 列表/批量/附件预览必须服务端强制 G4 scope，禁止仅前端过滤。
