# 统一事实导入规范 + 修复 3 个数据 Bug 实施计划

## 一、设计原则（贯穿全计划）

**所有事实数据写入必须经 `src/lib/performance-fact-repository.ts:replaceFactsBySource`（batch-replace 语义）**。任何绕过此 seam 的直写 DB 行为都视为不规范。

实施分 5 个阶段，按依赖顺序：

---

## 阶段 1：底层基础设施（先建基础，后续所有改动都依赖它）

### 1.1 扩展 `replaceFactsBySource` 支持 EmployeeBasicFact
- **文件**：新建 `src/lib/basic-fact-repository.ts`
- **职责**：为 `EmployeeBasicFact` 提供 `replaceBasicFactsBySource(prisma, scope, seeds, userIdByNo)`，与 PerformanceFact 的 seam 对称
- **scope**：`(year, dimension, sourceFile)` 三元组（dimension 是 SKILL_LEVEL/TITLE_LEVEL/PERFORMANCE_LEVEL）
- **去重 key**：`[year, employeeNo, dimension]`（与现有 unique 一致）
- **删除范围**：仅清该 `(year, dimension, sourceFile)` 下的旧记录；不同 sourceFile 共存的记录保留（避免新 sourceFile 上传时把旧 sourceFile 的合规记录误删）
- **不改动**：`replaceFactsBySource` 本体逻辑不变，basic 版本对称实现

### 1.2 修 B4：报表跳过 profile 不全的员工
- **文件**：`src/lib/annual-quantitative-report.ts:112-117`
- **改动**：把 `throw new Error(...)` 改为软降级——`workYearsAsOf` 返回 null 时跳过该员工（不计入报表），同时记入 warnings 数组返回给调用方
- **接口扩展**：`buildAnnualQuantitativeReportRows` 返回值增加 `warnings?: string[]`；CLI 打印 warning
- **影响范围**：13 个 E2E 员工被自动跳过；435 真实员工不受影响

### 1.3 修 B2 根因确认 + 修操作票小 bug
- **文件**：`src/lib/ticket-execution-import.ts:182-198`
- **改动**：将"每角色每人各加 0.01"改为"每人每行只计 1 次 0.01"
- **方式**：把 `touched: Set<string>` 的检查从 `operationTicketCount` 移到 `addPoints` 前——只有第一次出现才加分
- **注释**：明确"操作票中同一票号四列按人计数，每人每条数据只计一次"（来自规则 xlsx 行 38）
- **背景**：现行代码已修复 steps-based bug，但还残留 role-col 重复加分小 bug（影响 45 人共 1.48 分）

## 阶段 2：UI 导入路径新增（5 个新维度）

### 2.1 共用导入路由模板
- **文件**：`src/app/api/admin/import/_shared/` 下复用现有 `ImportWizard.tsx` + `parse.ts` + `field-specs.ts` 模式
- **每个新维度 3 件套**：
  1. `field-specs.ts` 新增条目（字段、别名、提示）
  2. `src/lib/{dim}-import.ts`（计分 + 转 `PerformanceFactSeed[]`，**最后调 `replaceFactsBySource`**）
  3. `src/app/api/admin/import/{dim}/route.ts`（Zod 校验 + 调 lib）

### 2.2 五个新维度的设计要点

| 维度 | 路由 | 计分规则 | 关键去重 key |
|---|---|---|---|
| **tech-contrib（运规/两票修订/教材）** | `/api/admin/import/tech` | 教材/题库 3/次；两票修订 2/项；运规 2/项；按子维度分别入 3 个 dimensionCode | `(year, employeeNo, dimCode, defectRef=项目名, role, eventType)` |
| **competition（竞赛比武）** | `/api/admin/import/competition` | 国网竞赛 10、省公司 5、调考 5/2、知识竞赛 5/2；按"备注"列判定级别 | `defectRef=奖项名称` |
| **innovation（创新奖项）** | `/api/admin/import/innovation` | 管理/科技创新国网 5、省 3；QC/五小国网 4、省 2；按"奖项"+"级别"自动判分 | `defectRef=奖项名称` |
| **patent（发明专利）** | `/api/admin/import/patent` | 前 4 人按序 4/3/2/1；展开每个专利的 4 个发明人列为 4 条记录 | `defectRef=专利名+顺序` |
| **violation（违章）** | `/api/admin/import/violation` | 严重直接 -10/连带 -5；一般直接 -5/连带 -2.5；按"等级"和"人员类型"自动判分 | `defectRef=违章描述` |

### 2.3 修 B3：发明专利同人多次同序号
- **关键**：在 `patent-import.ts` 中，每行源数据展开为 4 个 PerformanceFactSeed，每条的 `defectRef` 必须包含**专利名+顺序**（如 `"国网山西…/实用新型#order=1"`），避免同一员工不同专利的同序号被去重
- **验证**：源 22 条 → DB 22 条（含李勇 4 条 order=1）

### 2.4 修 B1：运规合并单元格漏算
- **改动**：`src/app/admin/import/_shared/parse.ts:47-66` 的 `sheetToParsedFile` 添加合并单元格展开逻辑
- **方式**：读取 `sheet['!merges']`（SheetJS 标准字段），把每个 merge range 的 top-left 值回填到所有覆盖单元格
- **影响面**：所有用 ImportWizard 的导入都受益；运规、两票修订等含合并单元格的源文件都能正确解析
- **测试**：新增 `parse.test.ts` 覆盖 merged-cell 场景

## 阶段 3：迁移 basic 导入到 batch-replace

### 3.1 改造 `src/lib/basic-fact-import.ts:131-178`
- 把 `importBasicFacts` 内部的逐行 `findFirst` + `update/create` 循环替换为：
  1. `loadBasicFactTiers(prisma)` 读 tiers（保留）
  2. `buildBasicFactDrafts(...)` 转 drafts（保留）
  3. 按 `dimension` 分组为 3 批 seeds
  4. 对每个 dimension 调 `replaceBasicFactsBySource(prisma, {year, dimension, sourceFile}, seeds[dim], userIdByNo)`
- **N+1 消除**：`userIdByNo` 复用 `loadUserIdByEmployeeNo`（已经一次性查全部）
- **返回值**：`{total, created, updated, deleted}`（与 PerformanceFact 形态对齐）

### 3.2 删除/废弃死代码
- **文件**：`src/lib/basic-quality-import.ts`
- **动作**：整个文件标 `@deprecated`，并在文件头加注释指向 `basic-fact-import.ts`；保留测试但加 `it.skip` 并注释原因（避免误导）
- **不立即删**：保留作为参考；后续 PR 单独清理

## 阶段 5：校验脚本（C 项）

### 5.1 新建 `scripts/verify-imported-scores.ts`
- **职责**：连 DB → 读源 XLSX → 重算期望分数 → 与 DB 对比 → 输出差异报告
- **覆盖维度**（按重要性）：
  - 基本素质 3 维度
  - 安全贡献（SHARE 均分）
  - 缺陷治理（MATRIX 矩阵）
  - 两票执行（含操作票按项不按步校验）
  - 技术贡献 3 子维度（重点校验合并单元格是否展开）
  - 竞赛/创新/专利（重点校验同人多次同序号）
  - 违章
- **输出**：stdout 表格 + `data/generated/verify-report-{timestamp}.json` 详细差异
- **退出码**：0 = 全部匹配；1 = 有差异（可接入 CI/手工回归）
- **package.json**：新增 `"verify:imported-scores": "npx tsx scripts/verify-imported-scores.ts"`

### 5.2 接入回归流程
- 在 `docs/agents/fact-import-conventions.md` 中说明：每次导入后跑 `pnpm verify:imported-scores` 验证

## 三、实施顺序与提交粒度

按"先底层后业务、每阶段独立可提交"原则，分 6 个 commit：

1. **feat(facts): EmployeeBasicFact batch-replace seam + B4 软降级 + B2 操作票去重**（阶段 1，最小破坏）
2. **feat(import): parse.ts 合并单元格展开 + 5 个新维度导入路由**（阶段 2，修 B1+B3）
3. **refactor(import): basic-fact-import 迁移到 batch-replace + 废弃 basic-quality-import**（阶段 3）
4. **docs(facts): 事实写入规范 + restore 脚本迁移到 src/lib**（阶段 4）
5. **feat(verify): 导入分数校验脚本**（阶段 5）
6. **chore(data): 重导入 4 维度 + 重生成报表**（阶段 6，可能需手工操作 UI）

每个 commit 都先跑 `pnpm test && pnpm lint`，确保不破坏现有测试。

## 四、风险与缓解

| 风险 | 缓解 |
|---|---|
| 改 parse.ts 影响现有维度导入 | 新增 merged-cell 处理是纯增量（无 merge 时行为不变）+ 加测试 |
| basic-fact-import 改 batch-replace 改变 sourceFile 行为 | scope 含 sourceFile，旧 sourceFile 的记录不受影响；只清同 sourceFile |
| 5 个新维度 UI 未对接 | 后端路由 + lib 先就位；前端 ImportWizard 只需在 `_shared/field-specs.ts` 加条目即可自动出现 |
| 重导入可能误删现有正确数据 | 先 `pnpm verify:imported-scores` 留 baseline；重导后对比 |
| `replaceFactsBySource` scope 含 sourceFile 导致不同批次共存 | 这是设计意图（同维度多源数据并存），但需在规范文档明确 |
